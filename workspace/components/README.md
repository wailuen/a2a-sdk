## Descriptions

**C-001 crypto** (`agent_sdk/credentials/crypto.py`)
Shared AES-256-GCM encryption module extracted from EncryptedSqliteStore. Exports `derive_key`, `encrypt`, `decrypt`, and `PBKDF2_ITERATIONS`. Reusable by any backend that needs authenticated symmetric encryption with namespace/field AAD binding.

**C-002 CommitmentBackend** (`agent_sdk/contrib/commitments/backend.py`)
Abstract base class extracted from CommitmentStore. Defines the public contract (`add`, `claim_due`, `mark_fired`, `mark_failed`, `cancel`, `reap_stale_firing`, `get`, `list`, `close`) so Azure Table Storage and any future durable-store implementations can be swapped without touching CommitmentExecutor or CommitmentsSource.

**C-003 SubscriptionBackend** (`agent_sdk/contrib/webhooks/backend.py`)
Abstract base class extracted from SubscriptionStore. Defines the public contract (`initialize`, `upsert`, `set_expiration`, `delete`, `get`, `list`, `due_for_renewal`, `close`) so GraphSubscriptionManager and webhooks_renewal_lifespan can accept any backing store (SQLite, Azure Tables, in-memory) via dependency injection.

**C-005 TaskStore** (`agent_sdk/tasks/store.py`)
Abstract base class for the SDK's task lifecycle store. Defines the public contract that `InMemoryTaskStore` (`agent_sdk/tasks/memory.py`) implements and that external durable-store implementations (e.g. AzureTableTaskStore) must satisfy. Key public methods: `create`, `get`, `subscribe`, `unsubscribe`, `find_interrupt`, `publish`, `close_streams`, `mark_interrupted`, `deliver_resume`, `interrupt_ttl_remaining`, `evict`, `sweep`, `close_all`, and `context_messages`. Breaking change in w022: `list_tasks_for_identity` return type changed from `tuple[list[Task], str | None]` to `tuple[list[Task], str | None, int]` — the third element is the total count of all matching tasks regardless of cursor position. External `TaskStore` subclass implementors must update their `list_tasks_for_identity` signature to match. w031/AGUI-1 (RT-002, non-breaking): added `interrupt_ttl_remaining(task_id) -> float | None`, a relative-seconds-to-expiry hook the AG-UI route now reads instead of the old absolute `record.interrupt_deadline` when serializing `Interrupt.expiresAt`. The base-class default returns `None` (unknown) so pre-existing external `TaskStore` subclasses keep instantiating without an override — but they will silently stop emitting `expiresAt` on AG-UI interrupt outcomes (previously an absolute, monotonic-clock-derived `int` was emitted; now nothing is, rather than a wrong value). External subclassers who want `expiresAt` back must override `interrupt_ttl_remaining` to compute seconds-remaining from their own store's tracked deadline and clock. Call this out explicitly in the 0.5.40 CHANGELOG entry under "Breaking/behavior changes for TaskStore subclassers".

**C-006 A2uiCapabilityGate** (`agent_sdk/a2ui/translator.py (alongside A2uiCapabilities)`)
Fail-closed per-transport A2UI capability resolver. `A2uiCapabilities.gated(opted_in: bool, raw: Any) -> A2uiCapabilities` (RT-005) is the one place the fail-closed default is defined: `opted_in=False` always returns `tier="none", catalogs=[]` regardless of *raw*; `opted_in=True` delegates to `from_metadata(raw)`. `agent_sdk/routes/a2a.py`'s `_capabilities` (gates on the A2UI extension URI being present in `X-A2A-Extensions`) and `agent_sdk/routes/ag_ui.py`'s `_capabilities` (gates on `forwardedProps.a2uiClientCapabilities` being present) both now compute their own transport-specific `opted_in` boolean and `raw` value, then delegate entirely to `A2uiCapabilities.gated`. Prevents recurrence of LRN-046 across transports — any future transport must route through `gated` too rather than reimplementing the none-tier fallback inline.

**C-007 safe_error_text** (`agent_sdk/common/redact.py`) — landed (RT-006, wave following GH-130)
Shared truncate+control-char-strip helper for building error messages from untrusted (model-/caller-supplied) strings, guarding SI-2 log/wire injection. `safe_error_text(value, *, max_len=64)` translates the full `str.splitlines()` break set (C0 controls 0x00-0x1F — includes CR/LF/VT/FF/FS/GS/RS — plus DEL, C1 controls 0x80-0x9F which includes NEL 0x85, plus U+2028/U+2029) to a space, then strips; `max_len=None` skips truncation for callers that must preserve the untrusted value's full length. `agent_sdk/agent/loop.py`'s `_sanitize_model_name` (the former inline `tc.name[:64].translate(dict.fromkeys(range(0x20), " "))` idiom, by then already widened in-place to include DEL/C1) now calls this instead of re-deriving its own control-char map. `agent_sdk/models/content_types.py`'s `_sanitize_cell` (GH-130/RT-004's delimiter-safety sanitiser for `to_plain_text()` renders) calls `safe_error_text(value, max_len=None)` and layers `|`/U+2502/U+FF5C confusable-replacement on top — the reuse this component was registered to enable, closing the RT-006 finding that the original GH-130 patch implemented an equivalent helper inside content_types.py instead of landing it here. Any future caller needing the same control-char/line-break neutralisation (GH-96's run_error path, ag_ui.py, etc.) MUST call this rather than re-deriving a fifth divergent copy.

**C-010 ToolEntry.invoke_any** (`agent_sdk/agent/registry.py`)
Shared is_generator/DeferredResult tool-dispatch helper (RT-001, follow-up to RT-002/LRN-116). `invoke_any(arguments, adapters, *, timeout=None, policies=None)` drains a coroutine or async-generator tool without the caller having to branch on `decl.is_generator`, and resolves a returned `DeferredResult` inline for callers with no background delivery channel. When `timeout` is given, it bounds the initial invoke/drain (`asyncio.wait_for`/`asyncio.timeout`, mirroring every other invocation surface) AND the DeferredResult handle under the SAME single deadline — the handle gets only the remaining budget, never a fresh `timeout` seconds on top (RT-003: previously `agent_sdk/routes/mcp.py` applied the full timeout twice sequentially). When `timeout` is omitted (the commitments executor's call shape — no per-call deadline of its own), the initial invoke/drain stays unbounded and only the DeferredResult handle is bounded, via `resolve_tool_timeout` against `policies` (or a default `LoopPolicies()`). Only the executor's CALL SITE is legacy/unchanged; the BEHAVIOR is not — RT-001: before GH-120 `invoke_any` returned the `DeferredResult` verbatim and `executor.py` dropped the handle unawaited (side effect never ran, yet the commitment was still marked fired). The handle is now awaited on this timeout-free path too, so a committed `long_running` tool is marked fired only after its deferred side effect completes (and failed if it times out) — proven end-to-end by `tests/test_rt002_invoke_any_deferred_result.py::test_executor_fire_actually_runs_deferred_handle` (real ToolEntry through the real CommitmentExecutor). `agent_sdk/routes/mcp.py`'s `_handle_tools_call` and `agent_sdk/routes/admin.py`'s `try_tool` both now call this (previously each re-implemented the `is_generator` branch inline, and `admin.py`'s `try_tool` didn't handle `DeferredResult` at all — silently trying to JSON-encode the raw object); `agent_sdk/contrib/commitments/executor.py` continues to call it with no `timeout`/`policies` (call site unchanged; the handle is now awaited rather than dropped). Any future error-mapping/timeout fix to tool dispatch belongs here, not in a fourth re-implementation. The nested-`DeferredResult`-resolution step itself is NOT inline here — it delegates to the separately-registered module-level helper **C-012 `resolve_deferred_result`**, which `runner.py`'s background deferred-job awaiter also calls directly (bypassing `invoke_any` entirely, since it isn't dispatching a fresh tool call). See C-012 for the cross-surface parity contract that split enforces.

**C-009 guard_origin** (`agent_sdk/common/origin.py`)

Any future change to allow-list semantics (`null` Origin handling, subdomain matching, case-folding) must land in this one function.

**C-011 dispatch_tool (generator-aware invoke helper, planned)** (`agent_sdk/agent/registry.py`)
w033 GH-115 fixed `routes/mcp.py`'s `_handle_tools_call` by routing it through the already-extracted `ToolEntry.invoke_any()` (C-010), NOT by building a new helper — so `dispatch_tool` as described here does not exist in code yet. It remains distinct from C-010: `invoke_any` unconditionally discards interim `LoopEvent`/`ToolProgressEvent` items when draining `invoke_gen()` (by design — its callers, `routes/mcp.py` and `routes/admin.py`'s `try_tool`, have no channel to forward them), and `agent/loop.py`'s tool-dispatch loop therefore still keeps its OWN separate inline `is_generator` branch (guarding `entry.decl.is_generator`) so it can forward `ToolProgressEvent` downstream to the live A2A/AG-UI stream — the exact duplication LRN-116's Prevention clause warns will recur on a future surface. A true `dispatch_tool` would generalize `invoke_any` with an optional progress-event callback (no-op by default, matching today's discard behavior; wired to the stream for callers like `loop.py`) so `loop.py`, `routes/mcp.py`, and any future invocation surface (e.g. a streaming MCP `tools/call` variant) share the ONE `is_generator`/`ToolTerminalResult` branch instead of `loop.py` and the registry each maintaining their own. Logged here as planned so the next surface or refactor that touches tool dispatch builds this instead of a third divergent copy.

**C-012 resolve_deferred_result** (`agent_sdk/agent/registry.py`)
Module-level (not `ToolEntry`-bound) nested-`DeferredResult` resolver, extracted out from under C-010 (RT-001). `resolve_deferred_result(result, *, tool_name, handle_timeout)` follows a chain of nested `DeferredResult` up to `_MAX_DEFERRED_RESOLUTIONS` deep (GH-120/GH-121), calling `handle_timeout()` fresh before each await so a caller enforcing one overall deadline (RT-003) can shrink the budget as time elapses; a resolution beyond the bound closes/cancels the handle and raises `AgentError`. It is imported and called directly by **two independent modules**: `ToolEntry.invoke_any` (C-010, same module — MCP `tools/call`, admin try-tool, commitments executor) and `agent_sdk/agent/runner.py`'s `_run_deferred_background` (the A2A/AG-UI background awaiter for a `DeferredEvent`). This is the RT-001 transport-parity guarantee itself, scoped to nesting DEPTH: a nesting depth that succeeds resolving a `long_running` tool's result on one dispatch surface must succeed identically on every other, and the same holds for the point at which nesting is rejected as too deep. RT-002: that parity guarantee does NOT extend to the timeout budget spent resolving a chain. `runner._run_deferred_background` and a timeout-bearing `invoke_any` call both close `handle_timeout` over a single deadline computed once, so the remaining budget shrinks across nested awaits; `invoke_any`'s `timeout=None` shape (the commitments executor — its only caller with no per-call deadline of its own) instead re-derives a FULL `resolve_tool_timeout` budget before every nested await. A slow nested-`DeferredResult` chain can therefore succeed on the commitments surface while timing out on MCP/A2A for the identical tool contract — an intentional consequence of the commitments path having no deadline to shrink, not a drift bug. A future change wanting timeout-budget parity to match depth parity would need to thread a shared deadline through `CommitmentExecutor._fire` (e.g. a configurable per-fire timeout passed as `invoke_any(..., timeout=...)`), not a change to this helper. Any future third dispatch surface that awaits a returned `DeferredResult` MUST call this rather than re-deriving `_MAX_DEFERRED_RESOLUTIONS` inline — a re-implementation would silently reintroduce the exact cross-surface drift RT-001 closed.

**C-016 safe_block_text** (`agent_sdk/common/redact.py`) — landed (RT-001, wave following GH-130)
The block-text counterpart to C-007 `safe_error_text`, for fields whose contract is a MULTI-LINE markdown document rather than a value interpolated into a delimited single-line render. `safe_block_text(value)` normalises `\r\n`/`\r` to `\n`, then translates every C0/DEL/C1 control char and U+2028/U+2029 to a space EXCEPT `\t`/`\n` (legitimate content in a markdown document, not structure) — so ANSI/terminal escape introducers (ESC 0x1B, CSI 0x9B), NEL, and the rest of C0/DEL/C1 are still neutralised (SI-2 holds) while headings, blank lines, list items, and markdown tables survive intact. `|` is deliberately left alone here (markdown table syntax, not a column delimiter this renderer joined on) — the opposite choice from `_sanitize_cell`/`safe_error_text`, which is why the two helpers are selected by the FIELD's contract, never by the enclosing method's name (see `ContentModel.to_plain_text`'s "Delimiter-safety contract" docstring in `agent_sdk/models/content_types.py`). Only call site: `agent_sdk/models/content_types.py`'s `_sanitize_block` wrapper, itself called from exactly two fields — `MarketBriefing.prose` and `TextSection.content` — the SDK's sole prose-exception type whose `to_markdown()` output IS the A2A/AG-UI DataPart value and the MCP `structuredContent {"markdown": ...}` payload. (Anchored by symbol name rather than line number so this entry cannot drift on unrelated edits to the file — RT-017/LRN-108.) Covered through `tests/test_content_types.py` (`test_market_briefing_prose_preserves_multiline_markdown`, `test_market_briefing_text_section_preserves_multiline_markdown`, `test_market_briefing_prose_still_strips_terminal_injection_chars` [parametrized: ESC/CSI/NEL/NUL], `test_market_briefing_prose_normalises_carriage_returns`) via `MarketBriefing`, and, since RT-014, directly in `tests/test_redact.py` (`test_safe_block_text_preserves_newline_tab_and_pipe`, `test_safe_block_text_normalizes_crlf_to_lf`, `test_safe_block_text_normalizes_bare_cr_to_lf`, `test_safe_block_text_neutralizes_escape_and_control_chars` [parametrized: ESC/CSI/NEL/NUL/U+2028/U+2029]) — closing the gap where a change to the helper that happened not to alter either MarketBriefing field render would pass unnoticed. Any future field whose contract is a markdown/prose document (not a delimited cell) MUST call this rather than re-deriving a control-char filter, and MUST NOT be routed through `safe_error_text`/`_sanitize_cell` — doing so silently flattens the document's structure.

**C-017 frame_locations** (`agent_sdk/common/redact.py`) — landed (RT-004, wave following LRN-044; extended RT-007)
SI-2-safe diagnostic formatter for a generic `except Exception` catch-all on a tool-dispatch or upstream-call surface: `frame_locations(exc, *, limit=5)` renders the last `limit` traceback frames as `file:line` pairs joined on `|`, using ONLY `FrameSummary.filename`/`.lineno` — never `.line`, which echoes source text that could itself embed a caller-derived literal. It exists because RT-010 found that dropping the traceback entirely (to satisfy SI-2) made genuine tool-body bugs undiagnosable (bare exception class name, no file/line); this helper restores diagnosability without the SI-2 risk of logging the exception's own message (which may embed caller/tool-derived data, e.g. a `ValidationError`'s `input_value=...`) or its full formatted traceback text. Eight call sites across six files share it. Four-file tool-dispatch core (RT-006/LRN-044's rewritten Check): `agent_sdk/routes/mcp.py`'s `_handle_tools_call` — the original, correct implementation — and, following RT-004 (which found admin.py's and loop.py's existing "mirrors mcp.py's catch-all" comments FALSE; both were still type-only), `agent_sdk/routes/admin.py`'s `try_tool`, all three of `agent_sdk/agent/loop.py`'s dispatch catch-alls — coroutine dispatch, generator dispatch, and resume-handler dispatch — and `agent_sdk/contrib/commitments/executor.py`'s `_fire`, added in the same wave alongside the GH-135 `ToolInputValidationError` split. The executor site is the RT-012 carve-out LRN-044's rewritten Check names explicitly as a parity surface: it fires in the background with no caller observing the failure, so on top of the same `frame_locations()` log line the other sites emit, its generic branch ALSO persists `type(exc).__name__` as the commitment's durable, operator-facing `last_error` column — the one place the exception class name is stored rather than only logged; the message/frames themselves are still never persisted. RT-007 extended the same contract to the SDK's two model clients — `agent_sdk/agent/bedrock.py`'s `_log_and_wrap_upstream_error` and `agent_sdk/agent/openai_client.py`'s `converse()` generic `except Exception` — closing a gap RT-007 found: `redact.py`'s own docstring already claimed "both model clients" parity, backed by a named test that didn't exist yet, while `openai_client.py`'s catch-all was still bare with no logging at all and this registry entry still said "four files" (LRN-066: registry narrative must match landed code, not the aspiration). **C-018 safe_cell_text** (`agent_sdk/common/redact.py`) — landed (RT-002, round-5 fresh-lens debug)
The delimited-render member of the C-007 family, and the helper that actually discharges the GH-130 delimiter-safety contract. `safe_cell_text(value)` composes `safe_error_text(value, max_len=None)` (full `str.splitlines()` break set + remaining C0/C1 controls collapsed to a space, no length cap — a cell keeps its untrusted length) with the separator alphabet: `_BARE_SEPARATORS` (`|` and its confusables `│`/`｜`, plus `<`, `>`, `(`, `)`, `[`, `]`, `=`) neutralised everywhere to non-structural full-width look-alikes, and `_SPACED_SEPARATORS` (`:`, `,`, `@`, en/em dash, `→`) neutralised only where an occurrence could form the template's spaced joiner — so `alice@corp.com` and `09:30:00Z` survive intact while `" @ "`/`": "` joins cannot be fabricated. No replacement is itself a separator, so a neutralised character can never re-fabricate the delimiter downstream.
Why it is a registry component and not a module-private helper: the contract is declared MANDATORY for third-party code in three places (`ContentModel`'s docstring, DESIGN.md §4.0's stable-core list, `docs/content-types.md`), and until RT-002 the only implementation was `models/content_types._sanitize_cell` — private and unexported. Downstream domain cards could satisfy the rule only by hand-rebuilding the alphabet per card module (which `docs/content-types.md` explicitly instructed), i.e. the divergent second copy this registry exists to prevent; four consecutive review rounds each missed one more separator doing exactly that by hand. `safe_error_text` is NOT an acceptable substitute: it performs no separator neutralisation at all.
Call sites: `agent_sdk/models/content_types.py`'s `_sanitize_cell`, now a thin alias, through which every SDK renderer routes (~25 sites); third-party domain cards import it as `agent_sdk.safe_cell_text` (exported from `agent_sdk/__init__.py::__all__`, stable core, strict SemVer). Choose by the FIELD's contract: `safe_cell_text` for a value interpolated into a delimited single-line render, C-016 `safe_block_text` for a field whose contract is a multi-line markdown document. Tested by `tests/test_content_types.py` (`test_every_renderer_separator_is_neutralised`, `test_untrusted_value_cannot_alter_render_structure` — the two directions that make forgetting the helper a build failure) and `tests/test_rt009_redact_helpers_stable_export.py` (public-export stability, delegation-not-duplication, and that it neutralises what `safe_error_text` does not).

**C-019 wave_scope** (`harness/wave_scope.py`) — landed (RT-001 fix round; registered RT-003, round-5 fresh-lens debug; RT-006 path-shape fix; RT-009 relocated out of the wheel)
