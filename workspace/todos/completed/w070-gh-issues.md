Target: 0.26.0 (minor: new opt-in MCP behaviour for elicitation-capable clients and one new setting; sessions without the `elicitation` capability see no change).

Exception (encoding of ruling item 5, not a change of outcome): ruling item 5 says `accept → resume_handler(content)`. The SDK's resume handlers take the resume value, not bare content, so AC (outcome) delivers `content` inside the A2A data-resume envelope `{"status": None, "payload": content}` (GH-193, `agent_sdk/routes/a2a.py::_resume_value`) — the same value an A2A or AG-UI data resume hands the same handler. A bare dict without `status`/`payload` makes action_gate's `parse_decision` return UNCLEAR and deny, which would break ruling item 6 (test 13). Redteam rounds must not revert this envelope to bare `content`. This exception is wave-written: it is not a maintainer ratification. If the maintainer posts a clarifying comment on GH-224 confirming it, cite that comment URL here.

On Starlette 0.52.1's spec_version<2.4 path (`StreamingResponse.__call__`: a task group plus `listen_for_disconnect`), a client drop cancels the generator with `CancelledError`; uvicorn 0.40.0 HTTP reports 2.3, so the SDK's own server takes this path. The check runs before the pending entry is created. (2) `wait` → `resume`: the Future decides. The phase flips to `resume` in the same step the worker takes an `accept` result from the Future (no `await` between), so an accept that resolved the Future before the disconnect is always carried out under phase (c) shield, even when the disconnect lands before `resume_handler` starts; a disconnect that failed the Future first means `resume_handler` never runs. The worker's done-callback (sync, run by the loop) calls `_free()` only when the response has ended or the request task is done.
