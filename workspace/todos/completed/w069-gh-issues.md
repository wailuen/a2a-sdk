  - Root cause: `_VALIDATION_TYPE_PHRASES["literal_error"]` / `["enum"]` (loop.py:1067-1068) is a fixed phrase that never names the choices, so a client (e.g. Claude.ai over MCP) cannot correct its call.
  - AC (shared helper, test-first): promote the C-076 fit logic out of `_skill_catalog` (agent_sdk/routes/mcp.py:671) into `agent_sdk/common/text.py::cap_whole_entries(entries, limit, *, sep="; ", max_entries=None, omitted=0) -> tuple[str, int]`, registered as C-075 (its registered location; no third name). It returns (text, number of entries kept). `omitted` is the count of entries the caller already left out before the call; they are never in `entries`. Rule, one for both callers: keep whole entries in order; an entry that does not fit (`limit` counting the separator and a reserved tail) is skipped and later shorter entries are still tried (GH-246 skip-misfit); stop adding once `max_entries` are kept; N = `omitted` + entries of `entries` not kept; when N > 0 the text ends `<sep>…and N more` (ellipsis included, the C-076 tail), so `omitted > 0` always forces the tail and its length is reserved in the fit check for every entry. The "whole joined text fits, return it" shortcut (today mcp.py:676-678) runs only when `omitted == 0` and `max_entries` is `None` or `>= len(entries)`; a verbatim copy fails test (5), because `0..49` joined is about 188 chars, under 300, and would return all 50 values. `_skill_catalog` passes neither `max_entries` nor `omitted`, so its text stays byte-identical. `_skill_catalog` becomes `cap_whole_entries(entries, _MAX_SKILL_CATALOG_LEN)[0]` and its output stays byte-identical (`tests/test_gh205_mcp_skills.py` green unchanged). `loop.py` imports from `agent_sdk.common.text`, never from `routes/`. Failing tests RED before the code, GREEN after.
  - AC (phrase): for `literal_error` and `enum`, the phrase becomes `must be one of: <values>`. The values come from the **declared schema of `input_model`**, resolved by walking `loc` in the same single walk that renders the loc (refactor `_redact_loc` into one walk returning the rendered loc and the resolved annotation; no second walker): the `Literal[...]` args or the `Enum` member values of the field's annotation (unwrapping `Optional`/`Annotated`). In that walk the BaseModel branch tests the **unwrapped** `ann`, not the raw `current`, so a declared field under `n: Optional[N]` or `n: N | None` renders as `n.sort`, not `n.<key>` (today loop.py:1095 tests `isinstance(current, type)` on the raw annotation and gives `n.<key>`). Values are **not** taken from `err["ctx"]["expected"]`. Each value is rendered with `json.dumps` (default `ensure_ascii=True`) and cleaned with `safe_line_text`; a value whose cleaned text differs from its `json.dumps` text (cut at 256 chars with `…`, which would leave an unclosed JSON string the client cannot send back) is **skipped**, never shown cut, and counted in N by passing the skip count as `omitted`. The kept cleaned values go through C-075 `cap_whole_entries(values, 300, sep=", ", max_entries=20, omitted=<skipped count>)`, so the text ends `, …and N more` when values were left out (by the caller or by the helper); `loop.py` never writes its own tail. If no value is kept (all skipped), or the values cannot be resolved (no `input_model`, a `<key>`/`<extra>` segment, a custom type, a non-JSON-serialisable Enum value), the old fixed phrase is kept. The rejected input is never echoed (SI-2).
  - AC (docs): `docs/tools.md` `## Errors` lists the new `must be one of:` phrase for Literal/Enum fields, the 20-value / 300-character cap with the `…and N more` tail, that an over-long single value is left out, and the fallback to `value is not one of the allowed choices`.
  - AC (registry): `workspace/components/README.md` C-075 row moves to `agent_sdk/common/text.py::cap_whole_entries` and states the rule above; C-076 row says `_skill_catalog` is a caller of C-075 (no own fit loop); C-050 row adds the enum/literal allowed-values phrase. The two rows must not describe two helpers.
