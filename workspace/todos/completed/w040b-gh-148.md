- [x] `GH-148` No structural mechanism to thread a resolved identifier forward across turns — model recall substitutes a wrong-but-plausible value ‖ group:A
  - Creates: `agent_sdk/agent/reuse.py` (new module — `Reusable` result wrapper + `ReuseKind` input-field marker)
  - Modifies: `agent_sdk/agent/loop.py`, `agent_sdk/agent/registry.py`
  - Reads: `agent_sdk/agent/deferred.py` (mirror its `DeferredResult` pattern — dataclass wrapper + `isinstance` check in the loop, same shape, same file-per-concept convention), `agent_sdk/tasks/memory.py` / `agent_sdk/tasks/store.py` (confirm no new store is needed — the mechanism rides `messages`, which both A2A's `TaskRecord.messages`/`context_messages()` and AG-UI's client-resent transcript already carry)
  - Severity: high
  - Root cause: `run_loop`'s only cross-turn memory is replaying the full `messages` transcript verbatim; `result_cache` only dedupes byte-identical repeat calls within one task. There is no way for the model to reference a value it resolved in an earlier turn without retyping it from memory, and live testing (LRN-355 re-test, 8 fresh runs) found it substitutes a different-but-real, wrong entity's ID in 7/8 runs — a silent data-correctness failure with no validation-layer signal, since the substituted value is a real, valid ID.
  - Design (sdk-advisor, confirmed): a tool marks a return value reusable via `Reusable(value=result, kind="entity_id", label="PT IMC Pelita Logistik")` — same shape as the existing `DeferredResult` wrapper (`deferred.py:25`) and the same `isinstance` check pattern already in `loop.py` (~lines 480, 508). The loop unwraps `Reusable` before the model sees the result, and folds a `__resolved__(kind, label, value)` marker into that tool call's result block in `messages` — the same JSON block already folded today, so no new store or expiry rule. At the start of each `run_loop` call, the loop rebuilds a "resolved this conversation" index by scanning `messages` — identical logic for A2A (server-replayed `TaskRecord.messages`) and AG-UI (client-resent transcript), since both guarantee `messages` is complete every turn. An input field opts in via `Annotated[<type>, ReuseKind("entity_id")]` on the tool's Pydantic `input_model`.
  - AC: `Reusable` dataclass (value, kind, label) added to new `agent_sdk/agent/reuse.py`, mirroring `DeferredResult`'s `@dataclass(slots=True)` shape and module docstring style.
  - AC: `ReuseKind` marker class added to the same module, usable as `Annotated[str, ReuseKind("entity_id")]` on an `input_model` field.
  - AC: `loop.py` unwraps a tool's `Reusable` return value before the model sees the result (model receives `.value`), and folds a `__resolved__` marker (kind, label, value) into the corresponding tool-result message already being appended to `messages` — no new field added to `TaskRecord`.
  - AC: `loop.py` (or `registry.py`, whichever already introspects `input_model` fields) detects `ReuseKind`-annotated fields on a tool's `input_model` via `typing.get_type_hints(..., include_extras=True)`, and before invoking such a tool: (a) if the argument is the literal token `$ref:<kind>` or `$ref:<kind>:<label>` (to disambiguate between multiple resolved values of the same kind), substitute the real value and record the substitution as an auditable event (not silent — must be inspectable from stored state or an emitted event, not just an internal variable); (b) if the argument is a raw value that does NOT match any `__resolved__` value of that kind, and at least one resolution of that kind exists in `messages`, reject the call with a tool error instructing the model to re-resolve or use `$ref:<kind>` — this is the exact GH-148 failure mode, now caught instead of silently executed; (c) if no resolution of that kind exists yet, or the raw value matches, pass through unchanged.
  - AC: The rejection tool error does not leak the mismatched raw value or any resolved value's content verbatim (SI-2 — mirror the loc+type-only discipline `safe_validation_message` already uses elsewhere in this SDK; a generic "value does not match a previously resolved <kind>" is sufficient, the model doesn't need the leaked values to self-correct).
  - AC: `ToolEntry.invoke`/`invoke_gen` signatures are unchanged — the mechanism is purely additive; a tool that returns a plain value (no `Reusable`) and an `input_model` with no `ReuseKind`-annotated fields behaves exactly as today.
  - AC: New regression test reproducing the LRN-355/GH-148 repro scenario end-to-end against `run_loop` with `FakeModelClient` (mirror `tests/test_rt004_body_vs_input_validation.py`'s harness pattern): turn 1 calls a `Reusable`-returning resolver tool for "PT IMC Pelita Logistik" → `ENT_5831`; turn 2 (fresh `run_loop` call, full prior `messages` passed in — the AG-UI-shaped replay, per the issue's own repro methodology) supplies a WRONG raw ID (`ENT_6236`) for a `ReuseKind`-annotated field on a downstream tool → asserts the call is rejected with a corrective tool error, not silently executed; a follow-up call using `$ref:entity_id` succeeds with `ENT_5831` substituted.
  - AC: Regression test confirming a tool with no `Reusable`/`ReuseKind` usage is unaffected (byte-identical behavior to pre-change).
  - AC: CHANGELOG.md entry (additive feature, not breaking) describing the new `Reusable`/`ReuseKind` mechanism and the GH-148 fix it enables for downstream agents.
  - SI: SI-2 — rejection tool error must not echo the mismatched raw value or resolved value's content verbatim onto the wire.
  - GH: https://github.com/wailuen/a2a-sdk/issues/148
  - Reuses: C-007  # The new rejection tool error (AC line 20) and any `$ref:<kind>:<label>` token parsed out of a model argument are model-supplied strings heading for an error string and a log line. C-007 `safe_error_text` is the registered (planned) truncate+control-char-strip helper for exactly this; its landed inline form is `_sanitize_model_name` at agent_sdk/agent/loop.py:62 (_CONTROL_CHAR_MAP, [:64]). Route the kind/label token through that helper rather than adding a fifth divergent inline copy — C-007's registry entry already records three.
  - Reuses: C-011  # The ReuseKind pre-invoke gate is scoped to loop.py only, but loop.py is one of four dispatch surfaces. routes/mcp.py `_handle_tools_call`, routes/admin.py `try_tool` and contrib/commitments/executor.py all dispatch through C-010 `ToolEntry.invoke_any` and would silently bypass the gate — a tool whose ReuseKind field is guarded in conversation is unguarded over MCP tools/call. This is the exact cross-surface drift C-011 was logged to prevent (LRN-116 Prevention). Either place the gate where every surface reaches it, or add an explicit AC stating the gate is conversation-scoped by design and that non-loop surfaces pass through unguarded.
  - Reuses: C-005  # On A2A the only carrier for the `__resolved__` markers is C-005 TaskStore's `context_messages()`, whose base-class default returns `[]` (agent_sdk/tasks/store.py:155-163). Any external TaskStore subclass that does not override it silently disables the whole mechanism with no error — the same fail-quiet shape C-005's registry entry already documents for `interrupt_ttl_remaining`. Add an AC requiring this be called out in the CHANGELOG entry for TaskStore subclassers.
  - SI: SI-2  # The SI: line covers only the rejection error. AC (a) separately mandates that a successful `$ref` substitution be 'recorded as an auditable event ... inspectable from stored state or an emitted event' — that event carries the resolved value, and every LoopEvent the loop yields is mapped onto the A2A/AG-UI SSE stream and the admin console. A resolved value can be upstream data of any sensitivity. Extend the SI: line to bind AC (a)'s audit record to the same no-verbatim-value discipline (kind + label-hash or loc/type only), or state explicitly which surfaces the value may appear on.
  - SI: SI-2  # The `$ref:<kind>` / `$ref:<kind>:<label>` token is parsed from a model-generated tool argument, i.e. untrusted text, and both the substitution audit record and the rejection error will echo the kind (and possibly the label) back. No AC requires sanitising it. Add: the parsed kind/label must pass through the control-char-strip + length-cap sanitizer (loop.py `_sanitize_model_name` / C-007) before entering any error string, event payload, or log line.
  - SI: SI-2  # Trust-boundary gap not covered by any of SI-1..SI-7 (filed here as the nearest wire-data invariant). The design treats A2A and AG-UI as equivalent because 'both guarantee messages is complete every turn'. They are not equivalent in trust: A2A's transcript is server-replayed from TaskRecord.messages, AG-UI's is client-resent in the request body. If AG-UI carriage is later made to work, a caller can forge `__resolved__` markers in its own resent transcript and steer the substitution — the resolved-index must be documented as caller-controllable on AG-UI, and the guard must not be described as a data-integrity control on that transport.
