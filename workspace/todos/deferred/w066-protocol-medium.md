# w066 protocol-audit mediums/lows (deferred, 2026-10-25)

No critical/high from any advisor.

- [AG-UI/medium] The card (agent_sdk/routes/agent_card.py, _CUSTOM_EVENT_SCHEMAS, AGENT_ARTIFACT) declares valueSchema.data as type object. But agent_sdk/routes/ag_ui.py:445-446 sends data = payload.wire() for every ContentModel, and the prose type's wire() returns a bare markdown string (agent_sdk/models/content_types.py:1033). The non-model branch (ag_ui.py:450) can also send any JSON value. A consumer that validates against the card will drop or reject these frames. Fix: Change data in the AGENT_ARTIFACT schema to oneOf [object, string], or drop the type constraint. Add a test that checks each emitted AGENT_ARTIFACT value against the declared schema.

- [AG-UI/low] agent_sdk/routes/ag_ui.py:130-135 keeps only user and assistant messages. system, developer, tool and activity messages are silently discarded. RunAgentInput.tools (frontend tools) and .context are never read anywhere in the route. Static GenUI, where the frontend registers tool-bound components, therefore cannot work through this endpoint. The agent card does not say so. The fixed set of CUSTOM events is the only GenUI channel. Fix: Document in the card and docs/protocols.md that tools and context are ignored. Or map context[] into the system prompt and reject, or ignore with a notice, frontend tools.

- [AG-UI/low] threadId and runId are required by the schema. The route synthesizes them when absent (ag_ui.py:694-697, documented §5.3 ruling, GH-97). A resume entry with no status is accepted (ag_ui.py:781-785, status may be None). A client that omitted runId cannot tell which id was assigned unless it reads RUN_STARTED. This is deliberate leniency, not a wire break. The echoed ids are correct. Fix: No change needed if the ruling stands. Keep the leniency documented. Optionally require status on resume entries.

- [AG-UI/low] ag_ui.py:776 and 575 reject len(resume) != 1 with RUN_ERROR 'invalid resume entry'. The protocol allows several entries in one resume. This is safe today because the SDK emits only one interrupt per run. A generic client that resolves several interrupts in one request is rejected. Fix: Document the single-interrupt limit. Or loop over entries once multi-interrupt runs exist.

- [AG-UI/low] _emit (ag_ui.py:701-724) turns a serialization failure into a RUN_ERROR. If the RUN_STARTED frame itself ever failed to serialize (ag_ui.py:753), the stream would begin with RUN_ERROR and no RUN_STARTED. The code comment says this cannot happen because the ids come from loads_strict or uuid4. It is unreachable today. Fix: Optional: skip the guard for the first frame, or emit a RUN_STARTED with fresh uuid ids before any RUN_ERROR.

- [AG-UI/low] On a resume run, ag_ui.py:399-413 injects TOOL_CALL_START, then TOOL_CALL_ARGS with delta '{}', then TOOL_CALL_END before TOOL_CALL_RESULT. This satisfies strict clients (START, at least one ARGS, END, RESULT). But it re-announces the same toolCallId with empty args. A client that stores tool calls by id may overwrite the real arguments sent in the earlier, interrupted run. Fix: Document it. Or carry the original arguments into the resume record so the synthetic ARGS is faithful.

- [AG-UI/low] A2UI_UPDATE is sent as CUSTOM name A2UI_UPDATE with value {messages:[...]} (ag_ui.py:473-474, GH-214 ruling). The generic AG-UI/A2UI convention puts the A2UI payload directly in value. The envelope is declared in the card valueSchema, so SDK clients are fine. A generic AG-UI A2UI renderer must unwrap value.messages. The name routing is consistent: the five CUSTOM names in ag_ui.py, CUSTOM_EVENTS in agent_card.py and chat.js match exactly (traps 11 and 15 clear). Fix: Keep it documented. Mention the envelope in docs/protocols.md for third-party clients.

- [AG-UI/low] The card advertises AG-UI in two places. One is the capabilities extension https://agent-sdk.dev/extensions/ag-ui-run/v1 with params.endpoint (agent_card.py:174-177). The other is the top-level x-agui block, with transport, endpoint and customEvents objects (agent_card.py:225-229). Neither uses urn:agui:run:v1. The run endpoint URL is declared in both, so trap 14 is clear. A consumer that only matches urn:agui:run:v1 will skip AG-UI for this agent. Fix: Optionally also publish urn:agui:run:v1. Document the two forms so consumers detect both.

- [MCP/medium] agent_sdk/routes/mcp.py:997 - when a tool declares `emits` (so tools/list advertises `outputSchema`) but returns None, tools/call answers `isError:false` with empty text and NO `structuredContent`. The spec says a server that declares an outputSchema MUST return conforming structuredContent. The code comment says MCP only requires it when there is output to describe, but the spec has no such carve-out. Strict clients (the TS and Python SDK clients in Claude Code and others) reject this result with an error such as 'has an output schema but did not return structured content'. The cross-surface parity argument (A2A/AG-UI fold None to success) does not override the MCP MUST. Fix: Choose one: (a) for a None result on an emits-declaring tool, return `isError:true` with a fixed message like 'tool produced no output'; (b) omit `outputSchema` in tools/list for tools that may return None; or (c) make the output schema nullable and return structuredContent as an empty/neutral conforming object. Add a test: tools/list entry with outputSchema + void tool -> tools/call must either carry structuredContent or isError:true.
