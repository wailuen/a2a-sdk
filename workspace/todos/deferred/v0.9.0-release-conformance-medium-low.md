## Findings (verbatim from Leg 3)

**Known** means it is already recorded in `workspace/todos/deferred/w04*-medium-low.md`. Everything else is new.

**MCP (server)**
- M (new): `common/limits.py:49-52`, `auth/middleware.py:57-61`. A forwarded address that includes `ip:port` is not cleaned up. This gets around the rate limit and the cap on sign-ins in progress per address. (w043 only records a missing test for faked forwarded addresses, not this.)
- M (new): `routes/mcp.py:117,767-774`. The server claims to support MCP version 2025-03-26. But it rejects requests that lack the `MCP-Protocol-Version` header, and clients on that version never send it.
- L (new): `mcp.py:658-663`. A tool that returns nothing still declares an output format but sends no structured result. This was a deliberate choice for consistency with the other protocols.
- L (new): `mcp.py:400,554`. An unknown tool returns error code -32601. The spec example uses -32602.
- L (new): `mcp.py:465-473`. A bad page cursor is silently treated as the first page instead of returning an error.
- L (new): `mcp.py:851`. `GET /mcp` ignores an unknown session id instead of returning 404.
- L (new): `mcp.py:381`. A client message that is only a reply gets status 200, not 202.
- L (new): `middleware.py:93`, `oauth.py:969`. The "too many requests" reply on `/oauth/*` uses a body shape that is not the OAuth error format.
- L (new): `oauth.py:248,283`. Callback addresses like `vscode://` and IPv6 addresses are rejected. This is on purpose.
- L (locked ruling): `oauth_tokens.py:139,478`. A token for the bare site address is accepted at `/mcp`, and the other way round. Do not change it.
- L (new): `oauth.py:538,964`. The requested `scope` (permission list) is echoed back without being checked. It grants nothing.
- L (known, w042-A1 / w042-phase): `middleware.py:99-155`. The public helpers `resolve_identity` and `require_api_key_identity` ignore the switch that turns off API keys.
- L (partly known, w044 covers nearby non-Entra warnings): `oidc.py`, `app.py:511`. With an Entra tenant set but no role or group required, the server logs no startup warning. Any member of that tenant can sign in.
- Info (new): `app.py:696`. Automatic trailing-slash redirects are left on. Not tested.
- Info (new): `oauth.py:112`. The sign-in cookie is always marked secure, so Safari will not set it on plain-http localhost.

**A2A**
- M (new): `tasks/memory.py:252`, `routes/a2a.py:476`. After a resume, the task stays `input-required` (waiting for input) and is not set back to `working`. A second send in that gap gets the wrong error, -32001.
- M (new): `testing/chat.py:307-386`. A side effect of the item above: `ChatDriver.resume()` can raise a false "requires input" error.
- M (new): `routes/a2a.py`. The push-notification settings routes are missing. They fall through to -32601 instead of -32003.
- M (new): `console/static/chat.js:169-400`. In A2A mode, the console does not keep the `taskId` when an agent asks for input, so the next message starts a new task.
- M (new): `testing/chat.py:267-309`, `chat.js`, `selfcheck.js`. Request addresses are hardcoded instead of read from the agent card's `url`. This breaks when `PUBLIC_URL` has a path prefix.
- L (new): `a2a.py:363`. Incoming file and data parts are dropped silently.
- L (new): `a2a.py:137,394`. Wildcard output types like `*/*` are rejected.
- L (new): `chat.py:390`. `extract_reply` ignores a bare `Message` result.
- L (new): The console ignores the `X-A2A-Extensions` reply header and the `final:true` flag, and does not read A2A error codes. `_a2ui_active` is never used.
- L (new): `runner.py`. The SDK's extra metadata (`data_type`, `tool_name`, `audit`) is not declared as an extension.
- L (new): `a2a.py:286`. The credential-forwarding extension is echoed even when the card does not list it.
- L (new): `chat.py:39`. `NOT_AUTHENTICATED = -32007` is misnamed.

**AG-UI**
- M (new): `ag_ui.py:238,273`. `parentMessageId: null` is sent instead of leaving the field out. Strict TypeScript clients may reject null, but that is unverified. An earlier review ruling (REVIEWS.md Round 2) said to send null.
- M (new): No pinned `ag-ui-protocol` package and no test that checks each sent event against the official event shapes.
- M (new): `chat.js:641-656`. When the stream drops, the console sends the whole turn again as a new run, so tools may run twice.
- L (new): `chat.js:489`. The console retries 401, 403, 413 and 415 errors, which can never succeed on retry.
- L (new): `chat.js`. Partial-message events (`*_CHUNK`) are dropped if no start event came first.
- L (new): `chat.js`. Tool results show only an id.
- L (new): `chat.js`. A pending interrupt is cleared before the resume request succeeds.
- L (new): `chat.js`. User messages are sent as a parts array instead of plain text.
- L (new): `ag_ui.py:426`. The server accepts badly formed input instead of rejecting it with a 400.
- L (new): Client-defined tools are ignored, and nothing says so.
- L (new): The AG-UI extension address on the card is not the standard `urn:agui:run:v1`.

**A2UI**
- M (new; also seam S6): `a2ui/translator.py:108-118`. On A2A, domain-catalog components are sent even when the client did not list that catalog. The code comment's reasoning only holds for AG-UI.
- M (new): `console/static/a2ui.js:55-77`. `pointerSet` does not block `__proto__`, `constructor` or `prototype` in data paths, so agent-supplied paths can change shared JavaScript objects.
- M (new): `a2ui.js`. There is no cap on rows or segments when drawing.
- M (new; scope note): The console renderer is display-only. It draws only the root component, and has no child lists, inputs or actions.
- L (new): `a2ui.js:94-152`. One bad message stops processing of the rest. There is no per-message error catch.
- L (new): `a2ui.js:196`. A component missing a required field draws an empty card. The fallback is a JSON box, and the renderer lookup is not limited to its own entries.
- L (new): No A2UI is sent unless the client opts in, where the spec says to assume Core. This is deliberate. `default_capabilities` is unused.
- L (new): `content_types.py:244`. NaN or infinity in a required number turns into JSON null.
- L (new): `a2ui-agent-sdk` is not used. The prompt examples are illustrative, not the real wire shape.

**Seam**
- L (new; S4): The agent card advertises bearer tokens only. It gives no `oauth2` or `openIdConnect` pointer to the sign-in server, so clients can only find it through the 401 challenge.
